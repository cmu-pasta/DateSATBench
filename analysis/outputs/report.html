Which constraint features predict an encoding's speedup over simple?

Every benchmark instance is described by 37 static features computed from its constraint text. This page first shows how the instances group in feature space, then relates those features to how fast each SMT encoding solves the instance, relative to the simple baseline.

Reading it

When all three columns share a colour, the feature mostly tracks when the baseline gets slow, not which alternative to choose. Rows where the columns disagree are the ones that separate encodings.

Pooled correlations mix three very different corpora. Check Side by side before trusting a pooled cell.

Specialized router

A router looks at an instance's features before solving it and hands the instance to one encoding. Here it is measured on instances it has not seen, by cross-validation, and compared with always using one encoding and with the ideal router, the oracle, which picks the fastest encoding for every instance.

Feature correlation

Spearman correlation between every pair of features over all instances, ordered so that related features sit together. Green is positive and red negative, darker for a stronger correlation. Hover a cell for its exact ρ.

Feature reduction

Many features in the matrix above move together. Here every family of strongly correlated features is cut to a single feature, constant features are dropped, and the router is cross-validated again on only the features that are left, with the same setting and the same folds, to see what the dropped features were worth.

    Built by analysis/report/build_report.py from the pipeline outputs:
    1. datesat_parser.py: parse and fold the DSL
    2. extract_features.py → features.csv: 37 features per instance (definitions in features.md)
    3. join_results.py → joined.csv: one row per instance × encoding × run, with speedup
    4. cluster.py, solver_outcomes.py, plot_speedup_heatmap.py, plot_feature_correlation.py: 2D and 3D projections, outcome tables and PNG plots
    5. select_features.py → selected_features.json: one feature per family of correlated features
    6. crossval_router.py → model_cross_validation/ and train_router.py → model/: the specialized router, cross-validated and trained on every instance; crossval_router.py --selected → model_cross_validation_selected/: cross-validated on the selected features only
    7. build_report.py → this page
