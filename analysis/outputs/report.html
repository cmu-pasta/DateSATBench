Which constraint features predict an encoding's speedup over simple?

Every benchmark instance is described by 37 static features computed from its constraint text. This page first shows how the instances group in feature space, then relates those features to how fast each SMT encoding solves the instance, relative to the simple baseline.

Reading it

When all three columns share a colour, the feature mostly tracks when the baseline gets slow, not which alternative to choose. Rows where the columns disagree are the ones that separate encodings.

Pooled correlations mix three very different corpora. Check Side by side before trusting a pooled cell.

Encoding

Each encoding solves a different subset of instances, so the median over its own solves favours encodings that give up on the hard ones. The median over instances solved by every encoding compares them on the same work. “Beats it” counts speedups above 1 over the baseline, including one-sided timeouts at their bound. Median exact speedup uses only pairs both sides solved.

Specialized router

A router looks at an instance's features before solving it and hands the instance to one encoding. Here it is measured on instances it has not seen, by cross-validation, and compared with always using one encoding and with the ideal router, the oracle, which picks the fastest encoding for every instance.
